# Plan de Reconversion : Devenir Legal AI Specialist en 10 Semaines
### Édition Salarié·e en Activité — Inputs complets, micro-tâches, templates prêts à l'emploi

> **Profil cible** : Rédactrice juridique en poste, sans background technique, souhaitant se reconvertir en Legal AI Specialist **sans quitter son emploi**.
> **Durée** : 10 semaines | **Charge minimale** : 1h30/jour en semaine + 3h le samedi (~10–13h/semaine)
> **Principe directeur** : Chaque action tient dans un créneau de 30 min. Rien ne nécessite une demi-journée libre.

---

## ⚠️ Lire en premier : Guide du salarié·e en reconversion

### Votre réalité : vous avez déjà un travail

Ce plan est conçu pour une personne qui rentre fatiguée le soir, qui a des réunions imprévues, des pics d'activité au bureau, et pas toujours l'énergie de tout faire. **C'est normal. Le plan en tient compte.**

**Les 5 règles d'or pour réussir en travaillant :**

| Règle | Pourquoi |
|-------|----------|
| **1. Micro-tâches de 30 min maximum** | Le cerveau assimile mieux en petites doses. 30 min régulières > 3h irrégulières. |
| **2. Utiliser le trajet domicile-travail** | Podcasts, vidéos en écoute, lectures légères = 20–40 min/jour offerts |
| **3. Le samedi matin est sacré** | 3h sans interruption le samedi remplacent 6h d'efforts en soirée |
| **4. Pratiquer avec vos vrais dossiers** | Testez les outils IA sur des documents de votre travail actuel (anonymisés). Vous apprenez ET vous gagnez du temps au bureau. |
| **5. Ne pas rattraper — continuer** | Si vous ratez une soirée, ne vous sentez pas en retard. Continuez simplement le lendemain. |

### Planning type pour un jour de semaine

| Créneau | Durée | Activité |
|---------|-------|----------|
| Trajet matin | 20 min | Podcast ou vidéo (mode écoute passive) — voir liste recommandée |

**Soit ~1h40 à 2h/jour sans effort surhumain.**

### Planning type pour le samedi

|---------|-------|----------|
| 09h00–09h15 | 15 min | Relire les notes de la semaine, définir l'objectif du matin |

| 11h00–11h15 | 15 min | Pause obligatoire |

> Vous n'avez eu que 30 min cette semaine ? Voici le **minimum vital** par phase :

| Phase | Action minimale (30 min/semaine) |

**📌 Concepts clés à retenir cette semaine :**

- **Prompt** : instruction que vous donnez à l'IA
- **Hallucination** : quand l'IA invente des faits — toujours vérifier les données juridiques
- **Token** : unité de mesure du texte pour les LLMs (~4 caractères = 1 token)
- **Context window** : quantité de texte que le modèle peut lire en une fois (GPT-4o = ~128k tokens, Claude = ~200k tokens)

**📌 Points clés RGPD à maîtriser absolument :**
- 6 bases légales du traitement (consentement, contrat, intérêt légitime…)
- Droits des personnes : accès, rectification, effacement, portabilité, opposition
- Obligations : registre des traitements, AIPD, DPO, notification de violations
- Sanctions : jusqu'à 4% du CA mondial ou 20M€

**📌 AI Act — ce qu'il faut savoir pour un entretien :**
- Systèmes IA interdits (manipulation, scoring social) vs à haut risque (recrutement, justice)
- Obligations pour les fournisseurs et utilisateurs de systèmes à haut risque
- Marquage CE pour les systèmes IA à haut risque
- Entrée en vigueur progressive : 2025–2027

**📌 Concepts Make.com à comprendre :**
- **Scénario** : enchaînement d'actions automatiques
- **Déclencheur (trigger)** : événement qui lance le scénario (ex : nouveau formulaire rempli)
- **Module** : une action dans le scénario (ex : envoyer un email, créer un fichier)
- **Webhook** : URL qui reçoit des données en temps réel depuis une autre application
- **Filtre** : condition qui arrête le scénario si les critères ne sont pas remplis
- **Routeur** : branche le scénario selon des conditions (si A → chemin 1, si B → chemin 2)

**🎯 Workflow simple à construire cette semaine (étape par étape) :**
```

3. Connecter votre compte Google (autorisation OAuth)
4. Ajouter un module : Gmail → "Send an Email"
5. Dans le corps de l'email, insérer les variables du formulaire (prénom, objet…)
6. Activer le scénario et tester avec une soumission réelle
7. Prendre une capture d'écran du scénario actif et la coller dans Notion

**📌 Guide pas-à-pas — Appeler l'API OpenAI dans Make.com :**
```
1. Dans Make.com, ajouter un module "HTTP → Make a request"
2. URL : https://api.openai.com/v1/chat/completions
3. Méthode : POST
4. Headers :
   - Content-Type: application/json
   - Authorization: Bearer [votre clé API]
5. Body type : Raw / JSON
6. Corps JSON :
{
  "model": "gpt-4o",
  "messages": [
    {"role": "system", "content": "Tu es un juriste expert."},
    {"role": "user", "content": "{{1.contenu_du_formulaire}}"}
  ],
  "max_tokens": 500
}
7. Cliquer "Run once" pour tester
8. Dans la réponse, la réponse texte est dans : data > choices > 0 > message > content
```

**📌 Lexique minimal API :**
- **API** : interface qui permet à deux logiciels de communiquer
- **Endpoint** : l'URL précise qui reçoit votre requête (ex : /v1/chat/completions)
- **POST** : envoyer des données à l'API (opposé de GET qui récupère)
- **JSON** : format de données structurées en texte (clés + valeurs)
- **Bearer token** : votre clé API = votre mot de passe pour utiliser l'API
- **Response** : la réponse que l'API vous renvoie

#### Semaine 7 — Projet 1 : Custom GPT d'Analyse de Contrats

| Élément | Détail |
|---------|--------|
| **Objectif** | Créer un assistant IA spécialisé dans l'analyse de contrats, personnalisé avec vos règles d'analyse |
| **Outils** | ChatGPT-4o Custom GPT Builder (aucun code requis) |
| **Charge** | 45 min/soir + 3h samedi |

**🗓️ Plan jour par jour :**

| Jour | Durée | Action |
|------|-------|--------|
| Lundi | 30 min | Aller sur chatgpt.com → "Explore GPTs" → "Create". Lire le guide officiel (5 min). Écrire la première version du system prompt (voir ci-dessous). |
| Mardi | 45 min | Configurer le GPT : nom, description, instructions (system prompt complet), comportement. |
| Mercredi | 45 min | Tester sur un CDI : copier-coller le texte → noter ce qui fonctionne / ce qui est à améliorer |
| Jeudi | 30 min | Itérer sur le system prompt selon les résultats du test CDI |
| Vendredi | 30 min | Tester sur un NDA. Comparer les résultats CDI vs NDA. |
| Samedi | 3h | Tester sur un 3e contrat. Publier le GPT (accès restreint ou public). Créer la documentation portfolio dans Notion (captures avant/après, description du cas d'usage). |

**🔧 System prompt complet pour votre Custom GPT (copier-coller dans "Instructions") :**
```
Tu es CLAUSAL, un assistant juridique expert en analyse de contrats français.

TON RÔLE :
- Analyser tout contrat soumis par l'utilisateur
- Identifier les clauses à risque avec un niveau de gravité (🔴 élevé / 🟡 moyen / 🟢 faible)
- Détecter les clauses manquantes habituelles pour ce type de contrat
- Proposer des reformulations pour les clauses problématiques
- Ne jamais donner de conseil juridique définitif — toujours recommander de consulter un avocat pour les décisions importantes

FORMAT DE RÉPONSE SYSTÉMATIQUE :
1. 📋 RÉSUMÉ (5 lignes max) : parties, objet, durée, montant/contrepartie, résiliation
2. ⚠️ CLAUSES À RISQUE : liste avec niveau de gravité et explication en 2 phrases
3. ❌ CLAUSES MANQUANTES : liste des clauses absentes mais habituellement présentes
4. ✏️ REFORMULATIONS SUGGÉRÉES : pour les 2–3 clauses les plus problématiques
5. 📊 SCORE DE RISQUE GLOBAL : de 1 (contrat équilibré) à 5 (contrat très risqué), avec justification en 3 lignes

COMPORTEMENT :
- Toujours répondre en français
- Utiliser un langage juridique précis mais accessible
- Si le document soumis n'est pas un contrat, expliquer poliment ce que tu peux analyser
- Mettre en gras les termes juridiques importants
```

### Template Notion — Fiche RGPD vs AI Act

```
# 📋 Fiche RGPD vs AI Act — Synthèse essentielle

## RGPD (Règlement Général sur la Protection des Données)

### En vigueur depuis : 25 mai 2018

### 6 bases légales du traitement
1. Consentement — ex : newsletter
2. Contrat — ex : gérer une commande
3. Obligation légale — ex : conservation de factures
4. Intérêt vital — ex : urgence médicale
5. Mission d'intérêt public — ex : recherche publique
6. Intérêt légitime — ex : sécurité informatique

### Droits des personnes
- Accès (art. 15) : obtenir une copie de ses données
- Rectification (art. 16) : corriger des données inexactes
- Effacement (art. 17) : "droit à l'oubli"
- Portabilité (art. 20) : récupérer ses données dans un format lisible
- Opposition (art. 21) : s'opposer à certains traitements
- Limitation (art. 18) : bloquer temporairement un traitement

### Obligations pour les entreprises
- Registre des traitements (obligatoire dès 250 salariés ou traitement sensible)
- AIPD (Analyse d'Impact) pour les traitements à risque élevé
- Notification de violation à la CNIL sous 72h
- DPO obligatoire pour certaines organisations

### Sanctions
- Jusqu'à 4% du CA mondial OU 20 M€ (le plus élevé)

---

## AI Act (Règlement européen sur l'IA)

### Publication : 2024 — Entrée en vigueur progressive 2025–2027

### Catégories de risque
| Risque | Exemples | Obligation |
|--------|----------|------------|
| Inacceptable (interdit) | Manipulation, scoring social | Interdiction totale |
| Élevé | Recrutement, justice, crédit | Marquage CE, audit, transparence |
| Limité | Chatbots, deepfakes | Information de l'utilisateur |
| Minimal | Filtres spam, jeux vidéo | Aucune obligation spécifique |

### Obligations principales (systèmes à risque élevé)
- Évaluation de conformité avant mise sur le marché
- Documentation technique complète
- Supervision humaine obligatoire

## 10. FAQ — Questions fréquentes et déblocages

**Q : Je n'ai aucune formation technique. Est-ce vraiment faisable ?**
Oui. 90% de ce plan ne nécessite aucun code. Make.com, les Custom GPTs et Tally.so sont des outils visuels. Si vous savez utiliser Excel et envoyer un email, vous pouvez tout faire ici.

**Q : Et si je suis en retard sur le planning ?**
Pas de panique. Le plan est prévu pour 10 semaines mais peut s'étirer sur 14–16 semaines sans perdre en efficacité. Ce qui compte : avancer, pas aller vite.

**Q : Puis-je utiliser mes documents de travail pour m'entraîner ?**
Oui, en les anonymisant avant de les coller dans ChatGPT. Remplacez les noms, SIRET, adresses et montants par des données fictives. Ne jamais envoyer de données personnelles réelles à un LLM sans vérifier la politique de confidentialité de l'outil.

**Q : Faut-il publier sur LinkedIn même si on n'a pas encore de résultats ?**
Absolument. Vos premiers posts ne parlent pas de résultats mais de votre démarche. "Je teste X", "J'ai appris Y aujourd'hui", "Voici ce que j'ai découvert sur Z". C'est authentique et efficace.

**Q : ChatGPT peut-il faire des erreurs juridiques ?**
Oui, toujours. Les LLMs hallucinent — ils peuvent inventer des lois, des jurisprudences, des articles de code inexistants. **Règle absolue : jamais de conseil juridique basé uniquement sur l'output d'un LLM sans vérification.** Utilisez l'IA pour gagner du temps sur la forme et la structure, pas pour remplacer votre analyse juridique.

**Q : Que faire si un module Make.com ne fonctionne pas ?**
1. Regarder le message d'erreur exact
2. Le copier dans ChatGPT avec la question "Comment résoudre cette erreur dans Make.com ?"
3. Chercher sur YouTube "Make.com [description du problème]"
4. Chercher dans la communauté Make (community.make.com)

**Q : Dois-je créer une entreprise pour proposer des missions freelance ?**
Non pour commencer. En France, vous pouvez tester avec des micro-missions en portage salarial ou en auto-entrepreneur. La création d'entreprise peut attendre d'avoir les premières rentrées.

**Q : Comment savoir si je suis prêt(e) à proposer mes services ?**
Quand vous avez terminé au moins un projet portfolio fonctionnel (Projet 1 suffit), vous êtes prêt(e). Votre profil actuel de juriste + 1 projet IA concret est déjà différenciant.
